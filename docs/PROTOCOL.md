# USB и данные

## WaveStation 2012

- USBTMC: `05ff:0a21`. Режим USBRAW (`0a20`) не поддерживается.
- Команды без LF/NULL; пауза перед чтением — 0,2 с. Ответ собирается по длине USBTMC-заголовка порциями до 256 байтов, с учётом размера USB-пакета.
- Настройка начинается с OFF, отключает модуляцию, sweep и burst, устанавливает нагрузку HZ и проверяет параметры через BSWV?. Затем **Пуск** включает CH1.
- Параметры PULSE отправляются отдельными короткими командами. При тайм-ауте один раз повторяется только запрос чтения; команды изменения состояния не повторяются.
- Формы: SINE, SQUARE, PULSE, RAMP, DC. ARB-загрузка не реализована.

## Hantek DSO4104B

USB: `049f:505c`. Проверено на firmware `1.1.2(20201013.0)`.

`:WAVeform:DATA:ALL?` запрашивается для каждого пакета. Заголовок — 29 байтов: `#9` и три девятизначных поля (длина пакета, полный объём, смещение). Первые **99 байтов полезной нагрузки** — метаданные. Их удаляют после сборки; длины, покрытие и пересечения проверяются. Тестовые пакеты в `tests/fixtures/` синтетические.

Отсчёты — signed int8:

```text
voltage = polarity × code × volts_per_division / 25 − channel_offset
t[i] = i / actual_sample_rate
```

Затем применяются коэффициенты коррекции из конфигурации. Масштаб уже учитывает коэффициент щупа.

Некоторые ответы SCALe? содержат subnormal double: его биты трактуются как uint64 микровольт. Пример: `9.881e-319` → `0,2 В/дел`. Округление к ряду 1–2–5 выполняется только в пределах 0,1%.

Кадр содержит один канал. При чтении сохраняются и восстанавливаются состояния входов и RUN. Ноль времени — первый отсчёт; абсолютная привязка к триггеру не восстанавливается. Основной интерфейс использует CH1 → CH1, DC, щуп ×1 и автоматические масштабы. Это обновление отдельных кадров, не непрерывный поток.
